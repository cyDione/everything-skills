# Unity Scene、Prefab 与 Inspector 交接

首次编写或实质修改 Scene、Prefab、Inspector、UI 或 Input Actions 装配说明时读取本文件。

## 最小交接内容

- **前置条件**：Unity 和包版本、所需脚本、相关既有资产，以及本次代码已完成与尚未完成的部分。
- **资产清单**：准确的 `Assets/...` 路径、现存或待创建状态、Scene、Prefab、Variant 或 ScriptableObject 类型，以及由谁编辑。待创建资产要明确标注。
- **对象与组件**：Scene 完整层级或 Prefab 根对象、添加或复用的组件、启用状态和相关的 Transform、Layer、碰撞及相机设置。说明修改基础 Prefab、Variant 或场景实例 override。
- **字段与引用**：准确组件、序列化字段或 Inspector 标签、值和引用目标、对象或组件类型、单位、必填状态及默认语义。区分可配置字段与运行时只读状态，不要求手填运行时缓存。
- **事件与输入**：触发者、绑定位置、目标对象和组件、准确方法签名、UnityEvent 参数、调用顺序、重复绑定防护与解除责任。Input Actions 交接注明资产、Action Map、Action、类型、绑定及启用责任。避免同一事件由 Inspector 与 C# 重复绑定。
- **正常与异常流程**：正常、取消、失败及清理的职责和预期结果。项目确实采用 Visual Scripting 时才说明准确 Graph、Unit、端口及连接。
- **验证步骤**：要打开的场景、执行的输入和观察的状态、画面或日志，以及正常、边界和重试时的预期结果。Player 与真实手柄验证单独注明。

将具体操作步骤与原理说明分开。简单赋值列出准确值即可；对象归属、引用类型、参数或执行顺序容易配置错误时，给出足够的具体步骤。

## 完成检查

核对脚本类名、字段、可见性和方法签名，以及可读取资产中的既有 override。无法检查 Unity Editor 时标记“交接待执行”，不声称场景已装配。修改文本 YAML 时保留 GUID 和 fileID 关系并检查差异；静态文本可解析并不能证明 Unity 导入或引用有效。

避免创建已有能力的包装组件、重复校验或额外 Manager。重写交接后核对步骤是否完整、是否存在重复操作或无效引用，以及用户和开发者的资产职责是否改变。小任务可以简短，但仍须包含完成配置所需的信息。
