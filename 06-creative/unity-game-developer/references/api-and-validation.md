# Unity API 核验与验证证据

Unity 或包 API 不确定、涉及资产序列化迁移，或需要说明验证覆盖时读取本文件。

## 目标版本核验

读取 `ProjectSettings/ProjectVersion.txt`、`Packages/manifest.json`、`Packages/packages-lock.json` 和相关源码。对已解析的包，可阅读 `Library/PackageCache` 中源码与文档，但不可修改缓存。调用新 API 或项目尚未确认的 API 时，核对目标版本 Unity 手册、Scripting API、包文档或实际程序集。若版本资料不可得，说明证据限制并用最小 Unity 编译或运行验证补足，不用相邻版本的文档宣称兼容。

确认符号来自引擎、包、既有项目代码还是拟新增 helper，并核对命名空间、程序集、访问性、完整签名与重载、参数和返回类型、静态或实例语义、必要设置以及 Editor 或 Player 可用性。按任务相关性核实线程、生命周期、取消与清理。包内部符号不自动等于受支持的公开 API。不要用猜测方法名、反射或无依据版本分支掩盖未确认调用。

Inspector、UnityEvent 或 Visual Scripting 交接还须核对所用入口能否在相应上下文配置与调用；C# 方法存在不等于 Inspector 可绑定。记录源码位置或官方 URL、目标版本、准确契约与证据边界，区分源码已核实、编辑器已确认、项目 helper 待实现和未解决项目。无法确认的暴露方式或参数只阻塞相关步骤，不能交付猜测操作，也不能由单次查找失败断言不可实现。

参考入口：[Unity 手册](https://docs.unity3d.com/Manual/index.html)、[Unity Scripting API](https://docs.unity3d.com/ScriptReference/index.html)。任务开始时定位对应 Unity 版本的具体页面。

## 按影响范围验证

| 验证方式 | 能证明的范围 | 不能据此证明 |
|---|---|---|
| 文档与静态审查 | 实际检查范围内的契约、调用链、引用及逻辑推断 | Unity 导入、执行或实际体验 |
| Unity 导入与 C# 编译 | 指定工程和目标下脚本及程序集通过编译；还要检查导入错误 | Scene、Prefab 或玩法正确 |
| EditMode 测试 | 已执行的规则、数据或编辑器工具用例 | 未测的生命周期、场景和输入 |
| PlayMode 自动测试 | 已测生命周期或集成场景 | 未测试的用户操作、画面或设备体验 |
| 编辑器 Play 手动验证 | 指定场景与操作在编辑器中的表现 | Player 平台差异 |
| Player 构建 | 指定平台和后端构建成功 | Player 能正常运行 |
| Player 独立运行或设备验证 | 指定构建、设备、输入和场景的实际表现 | 未测设备及完整产品验收 |

纯规则改动优先覆盖行为不变量与有意义边界；生命周期改动覆盖重复进入、取消、销毁和重试；资产装配改动检查缺失引用和实际场景；构建相关改动再扩展到目标 Player。每项按真实影响范围选测，不因小改动强制执行完整测试套件。

使用与目标版本匹配的 Editor 和可用集成工具。Unity Editor 正占用工程时，不并行启动 batchmode 抢占同一工程，也不强制关闭现有 Editor。命令行测试须核对项目路径、筛选、日志和结果文件；进程退出码不足以证明测试成功，需确认编译错误、失败数量及测试实际执行数。Player 构建记录目标平台、后端、场景列表和日志。为单项小修改验证时，不升级 Unity、改动全局输入或渲染设置，也不清除 Library。

最终报告分别列明静态检查、Unity 编译、自动测试、Editor 验证、Player 构建、独立运行与实机输入体验。缺少 Editor、许可证或设备时，继续可做的静态工作，并将未执行项准确标明为“未执行”，附上适当的验证步骤。
